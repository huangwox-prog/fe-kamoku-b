# 出題スタイルガイド（科目B）

このサイトのオリジナル問題を作るときに守るルールです。
IPA が公開している科目Bの公開問題（令和5〜8年度）の**形式だけ**を観察してまとめたもので、問題文・コード・数値は引用していません。
公開問題そのものは `reference/` に置いていますが、著作物なのでリポジトリにもサイトにも含めません（`.gitignore` 済み）。

> **大原則**：公開問題と同じ題材・同じ数値・同じ処理の流れの問題は作らない。
> 形式（言い回し・記法・解答群の作り方）だけを合わせ、題材とアルゴリズムの組み立ては自分で考える。

---

## 1. 擬似言語の記述形式

### 1.1 全体の構成

- プログラムの前に見出し **〔プログラム〕** を置く。
- 関数・手続は行頭の **○** で宣言する。
  - 関数（戻り値あり）: `○戻り値の型: 関数名(型: 引数名, 型: 引数名)`
  - 手続（戻り値なし）: `○手続名(型: 引数名)` … 型を書かない。引数がなければ `○手続名()`
- 宣言の行が長いときは、引数の途中で改行して右に寄せて続けてよい。
- 一つの問題に関数・手続を複数並べてよい（呼び出し関係を問う問題など）。

### 1.2 型と宣言

- 型名: `整数型` `実数型` `文字型` `文字列型` `論理型`。ビット演算の問題では `8ビット型` のような型も使う。
- 配列: `整数型の配列` `文字列型の配列`、配列の配列: `整数型配列の配列`、二次元配列: `整数型の二次元配列`。
- 宣言: `型名: 変数名`。同じ型はコンマで並べられる（`整数型: i, j`）。
- 宣言と同時に初期化できる（`整数型: count ← 0`）。並べて書いた場合、`← 値` は直前の変数だけに掛かる。
- 大域変数は先頭に `大域:` を付けて、関数の外（プログラムの先頭）で宣言する。
- 論理型の定数は `true` / `false`。

### 1.3 配列

- **要素番号は 1 から始まる**（必ず問題文で注記する。→ 4章）。
- 参照は `a[i]`。二次元配列は `m[行, 列]`、配列の配列は `list[i][1]` の形。
- 配列の内容は `{` `}` で表す（例: `{2, 4, 6}`）。二次元配列は内側の `{ }` が1行分。
- 空の配列は `{}` とし、行末に `// 要素数0の配列` と注釈を付けることが多い。
- 要素数を決めて作るときは自然文で書く（例: `{n個の 0}`、`{r行c列の 未定義の値}`）。
- 要素数は `aの要素数`、文字数は `sの文字数` と書く。
- 値が入っていない状態は **未定義**。代入するときは `未定義の値` と書き、条件では `xが未定義` のように判定する。

### 1.4 代入・演算子

- 代入は `←`（`=` は使わない）。
- 演算子は**全角記号**で書く: `＋ － × ÷ ＝ ≠ ＜ ≦ ＞ ≧`。剰余は `mod`、論理演算は `and` `or` `not`。
- 整数の割り算は「`(a ＋ b) ÷ 2 の商`」のように **「の商」** と明記する。余りは `mod` を使うか「`÷ の余り`」と書く。
- 優先順位（高→低）: `()` とメンバ参照 `.` → 単項 `not ＋ －` → `mod × ÷` → `＋ －` → 関係演算子 → `and` → `or`。
  紛らわしいときは括弧で明示する（例: `(i mod 2)が0と等しい`）。
- 数学的な処理は自然文で書いてよい（例: `xの正の平方根`、`yの2乗`、`の整数部分`）。

### 1.5 制御構造

| 構造 | 書き方 |
|---|---|
| 選択 | `if (条件式)` … `elseif (条件式)` … `else` … `endif`（elseif は複数可、else は最大1つ） |
| 前判定の繰返し | `while (条件式)` … `endwhile` |
| 後判定の繰返し | `do` … `while (条件式)`（`endwhile` は付けない） |
| 回数・範囲の繰返し | `for (制御記述)` … `endfor` |

- `for` の制御記述は自然文で書く。
  - 増加: `i を 1 から n まで 1 ずつ増やす`
  - 減少: `i を n から 1 まで 1 ずつ減らす`
  - 刻み・上限が変わる: `j を k から始めて n を超えない範囲で 2 ずつ増やす` のような形
  - 配列の要素を順に取り出す: `x に list の要素を順に代入する`
  - 助詞の前後の空白はあってもなくてもよい（`iを1からnまで…` も可）。1問の中では統一する。
- 繰返しを途中で抜けるときは `繰返し処理を終了する` と書く。
  入れ子の外側を抜けるときは、対象の行に `// α` などの印を付け、`αの行から始まる繰返し処理を終了する` と書く。
- 条件式は記号でも自然文でもよい（`x ＞ y` / `nが3以下` / `aがbと等しい` / `aがbより大きい`）。
- 戻り値は `return 式`。手続は `return` を書かずに終わってよい。

### 1.6 自然文の処理・出力

- 配列への追加: `listの末尾 に xの値 を追加する`
- 入替え: `a[i]とa[j]の値を入れ替える`
- 出力: `"X" を出力する`、`resultの値を出力する`、`全要素の値を要素番号の順に空白区切りで出力する`
- 「〜の値」を付けて、変数そのものではなく値を扱うことをはっきりさせる。

### 1.7 注釈（コメント）

- `/* 注釈 */`（独立した行）と `// 注釈`（行末）の2種類。
- 用途は、(1) 境界の補足（例: `/* nが1以下のときは繰返し処理を実行しない */`）、(2) 処理のまとまりの見出し、(3) 設問で参照する行の印（`/*** α ***/`、`// β`）。

## 2. 問題文の言い回し

### 2.1 指示文（冒頭の1文）

問番号の直後に、何を答えるのかを1文で示す。主なパターンは次の4つ。

| 種類 | 言い回し |
|---|---|
| 空欄1つ（コード中） | 次のプログラム中の［　　］に入れる正しい答えを，解答群の中から選べ。 |
| 空欄複数（コード中） | 次のプログラム中の［ a ］と［ b ］に入れる正しい答えの組合せを，解答群の中から選べ。 |
| 空欄（説明文中） | 次の記述中の［　　］に入れる正しい答えを，解答群の中から選べ。 |
| 情報セキュリティ | 設問 …どれか。解答群のうち，最も適切なものを選べ。 |

- 「次の記述中の」型は、コードは完成していて、**実行結果・実行回数・出力・配列の最終状態**などを説明文中の空欄で問うトレース問題。
  - 例の形: 「関数 f を f(…) として呼び出すと，/\*\*\* α \*\*\*/ の行は［　］。」→ 解答群は「実行されない」「1 回実行される」…
  - 例の形: 「… の条件式が真となる回数は［　］回である。」
- 句読点は **「，」と「。」**（全角コンマ）。文字列を地の文で示すときは “ ” で囲む（コード中は " "）。

### 2.2 説明文

指示文のあとに、次の順で書く。

1. 関数・手続が何をするか: 「関数 xxx は，～を引数 n で受け取り，～を返す。」
2. 必要なら用語の定義（「本問では～という」）と、具体例（小さな入力と結果）。
3. 必要なら図・表（「図 1」「表 1」と番号と題名を付ける。未定義の要素は網掛け＋注記で示す）。
4. 制約（「ここで，引数 n は 1 以上とする。」「～が与えられることはないものとする。」）。
5. 見出し〔プログラム〕とコード。
6. 「解答群」。

## 3. 空欄と解答群

### 3.1 空欄の作り方

- 空欄は枠で示し、複数あるときは **a, b, c** の小文字で区別する。1問の空欄は 1〜3 個。
- 空欄にする場所の例:
  - `for` の制御記述の一部（開始値・終了値・増減の向き）
  - `while` / `if` の条件式
  - 代入の右辺（更新式）や配列の添字
  - `return` する式、関数呼び出しの引数
- 空欄の行だけでなく、**前後の行と組み合わせて初めて決まる**ように作ると良問になる（例: 更新式と終了条件の組合せ）。

### 3.2 解答群の並べ方

- 記号は **ア イ ウ エ オ カ キ ク ケ コ** の順。選択肢の数は 4〜10 個。
- 単独の空欄なら、似た式を系統的に並べる（例: 比較演算子の違い × 境界値の違い、のように変化させる軸をそろえて並べる）。
- 組合せの問題は**表形式**にする。列見出しに a, b（, c）を置き、
  **左の列を固定したまま右の列を変える**順で全組合せを並べる（2×2＝4、2×3＝6、3×3＝9、2×2×2＝8 通りなど）。
- 数値・文字列・配列の答えは、小さい順や辞書順など、規則的な並びにする。
- 「該当するものを全て挙げた組合せ」は、項番の組合せ（例: (一)，(三)）を辞書順に並べる。

### 3.3 誤答の作り方（このサイトでの方針）

- 受験者が実際にやりがちなミスから作る:
  境界の 1 ずれ（`＜`/`≦`、`n`/`n － 1`）、増減の向き、ループ回数の数え間違い、
  要素番号を 0 から数える、商と余りの取り違え、`and`/`or` の取り違え、早期 return の見落とし など。
- 正解は必ず 1 つだけにする（このサイトでは `verify` で機械的に確認する）。

## 4. 前提条件・注記の置き方

- 配列を使う問題では、指示文の直後に **「ここで，配列の要素番号は 1 から始まる。」** を続ける（指示文と同じ段落）。
- 範囲外参照の扱いを決めたいときは「プログラムでは，配列の領域外を参照してはならないものとする。」を説明文に入れる。
- 引数の範囲・前提は説明文で「～とする。」「～はないものとする。」と書く。
- ループが 1 回も回らない場合などの境界は、コード中の注釈 `/* … */` で補足する。
- 実数計算・ビット演算など特殊な規則は、説明文で定義してから使う（「～は，それぞれ～を表す。」）。

## 5. 長さの目安

| 項目 | 目安 |
|---|---|
| 説明文（指示文を除く） | 2〜6 文。具体例や図表を入れる場合でも 1 画面〜2 画面に収める |
| コード | 5〜30 行（基礎は 5〜12 行、標準は 10〜25 行） |
| 関数・手続の数 | 1〜3 個 |
| 空欄 | 1〜3 個 |
| 解答群 | 4〜10 個 |
| 1問の解答時間 | 本試験は 20 問を 100 分で解くので、1 問 5 分前後で解ける分量 |

- 公開問題では 6 問のうち 5 問がアルゴリズム、1 問が情報セキュリティ。
- 題材は、基本の制御（繰返し・条件分岐）から、配列操作、データ構造（スタック・リスト・ハッシュ）、整列・探索、再帰、文字列・数値変換、簡単な数理（行列・統計・ベクトル）まで幅広い。

## 6. 情報セキュリティ分野の形式

### 6.1 事例文

- 架空の組織で始める: 「A 社は，従業員 ○○ 名の ～（業種）である。」
- 現状の環境・運用・ルールを **図**（箇条書き）として示す（「図 1 A 社の～（抜粋）」）。
  補足は「注記」「注 1)」で書く。
- 登場人物は役割で示す（情報セキュリティリーダーの B さん、運用担当の C 主任、委託先の D 社 など）。
- 調査・評価の結果を **表**（項番・内容・評価）にまとめる。項番は「1, 2, 3」や「(一)，(二)，(三)」。
- 背景 → 現状 → 発見・課題 → 検討、の順に物語を進める。用語は ISMS・JIS Q 27001 系の一般的なもの（リスクアセスメント、RPO/RTO、2 要素認証、ログ管理、委託先管理 など）を使う。

### 6.2 設問の形

- 設問は 1 つ。頭に「設問」と付ける。
- 主な型:
  - 対策・リスクを選ぶ: 「～のうち，最も適切なものを選べ。」（解答群は文章 4〜5 個）
  - ルール違反の項目を全て選ぶ: 「～に違反しているものの項番だけを全て挙げた組合せを，解答群の中から選べ。」
  - 表中の空欄（a1～a3 のような番号付き）の組合せ: 「～に入れる字句の適切な組合せを，解答群の中から選べ。」
- 誤答は「もっともらしいが、事例の条件と合わない」もの（守る対象が違う、脅威の経路が違う、コストや運用面だけの話 など）にする。
- 正解の根拠が**事例文中の具体的な記述**から必ず導けるようにする。

## 7. このサイトの JSON への落とし込み

- `statement` の 1 段落目に指示文（「ここで，配列の要素番号は 1 から始まる。」を含む）を書き、2 段落目以降に説明文を書く。
- `code` の空欄は `［ a ］` のように全角の角括弧で示す。
- 組合せの解答群は、`choices[].text` を `a: ～ ／ b: ～` の形の 1 行にする。
- 解説（`explanation`）では、コードの行番号（サイトで自動表示される）を使って根拠を説明し、誤答ごとに「どんなミスでそうなるか」を書く。
- `verify.code` は擬似言語と同じ処理を JavaScript で書き、`expected` は正解の選択肢の `text` と一字一句同じにする。

## 8. 作問前チェックリスト

- [ ] 公開問題と題材・数値・処理の流れが重なっていない
- [ ] 指示文が 2 章のパターンに沿っている（全角コンマ「，」）
- [ ] 要素番号の注記がある（配列を使う場合）
- [ ] 演算子が全角、`←` で代入、`÷ … の商` を明記
- [ ] 空欄は a, b, c、解答群はア〜の順で系統的に並んでいる
- [ ] 誤答がそれぞれ具体的なミスに対応し、正解は 1 つだけ
- [ ] 長さが 5 章の目安に収まっている
- [ ] `node verify.js` が通る
